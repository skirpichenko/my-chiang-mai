# Мой Чиангмай: channel catalog

A searchable catalog of the public Telegram channel «Мой Чиангмай» (https://t.me/my_chiangmai), built from the channel's export and published with GitHub Pages at https://skirpichenko.github.io/my-chiang-mai/. The English version, at https://skirpichenko.github.io/my-chiang-mai/en/, follows the English channel @my_chiangmai_en.

**This repo is public.** Pages serves `docs/` from `main`. Never commit anything from `work/`: the export, contacts or extraction data. Never commit secrets, tokens or personal data either. The Telegram bots and other channel tools live in a separate private repo, which reads this folder's `work/result.json` as its export.

## Layout
- The site is static and mobile-first, and also works as a Telegram Mini App.
  - `docs/app.js` and `docs/app.css` hold all of it, with the strings of both languages, including each language's channel (`my_chiangmai`, `my_chiangmai_en`).
  - `docs/index.html` (Russian) and `docs/en/index.html` (English) are thin pages that set `window.SITE` and load them. The language link keeps the category.
  - Both pages load `app.css?v=N` and `app.js?v=N`. After changing either file, raise N in both pages, so browsers and Telegram fetch the new version instead of a cached one (Pages caches files for 10 minutes).
  - URL hash state: `#q=`, `#c=<category>`, `#city=`, `#area=<region id>`, `#past=1`.
  - The area list shows with the home city or all cities. Region names live in `app.js` for both languages, in the order of `tools/regions.json`; the footer credits OpenStreetMap, whose district borders the regions use.
  - The post button opens the post inside the card through Telegram's public embed (`t.me/<channel>/<id>?embed=1`), which needs no Telegram account or app.
- `docs/catalog.json`: generated by `tools/catalog.py build`. Never edit it by hand. The build strips tracking parameters (utm_*, fbclid, igsh, mibextid) from links.
- `docs/catalog.en.json`: the English catalog, generated by `tools/translate_catalog.py build` in the private channel-tools repo. It holds only the items whose posts are in the English channel, and its post ids are English channel ids. Never edit it by hand.
- `docs/.nojekyll`: tells Pages to serve the files as they are.
- `tools/catalog.py`: the pipeline. `status`, `diff`, `pending`, `build`, `split`; see the docstring.
- `tools/extract_prompt.md`: the extraction spec. It says how posts become entries: fields, the 20 category slugs, and the rules.
- `tools/extract_workflow.js`: a Workflow script that runs the extraction over many part files in parallel, with up to 4 parts per agent.
- `tools/geo.py`: city regions. `resolve` opens each short map link once and keeps Google's redirect in `work/geo.json` (network, one link a second); `build` then gives each item in Chiang Mai province its region as `z`, from the address in the redirect (subdistrict or district), the district borders, nearby places, or the area text. `stats` prints the counts.
- `tools/regions.json`: the 12 regions, built from the city's subdistricts and the province's districts, with their spellings and postcodes. `tools/regions/districts.json`: the province's district borders from OpenStreetMap (ODbL), written by `geo.py borders`.
- `work/`: **local only, git-ignored, never commit.** It holds the full export, including contacts.
  - `result.json`: the latest Telegram export. The private channel-tools repo reads it from here too.
  - `state.json`: a text hash for every post the catalog currently reflects.
  - `exports/`: archived raw exports.
  - `chunks/*.txt` and `out/*.jsonl`: the initial full extraction, done 2026-11-14 (70 parts, 5747 entries). Redoing it costs about 4.4M tokens, so never delete it.
  - `geo.json`: every map link with the address Google redirects it to. Rebuilding it takes about 1.5 hours, so keep it.
  - `inc/<tag>/`: one folder per update. It holds `p*.txt` (the changed posts), `p*.jsonl` (their entries), `posts.json` and `state_before.json`.

## How merging works
- Every post belongs to its newest extraction. When an update re-extracts a post, older entries lose that post id, and an entry with no post ids left is dropped. Deleted posts drop out on their own.
- `build` deduplicates entries:
  - events by name and date;
  - places by map link plus a similar name. Two different links that open the same Google place count as one link: `geo.py`'s `place_ids` reads the place's id from the link or from its redirect in `work/geo.json`. This merged about 300 duplicates on 2026-11-20 (5680 -> 5370 items). A link with no place id (a search, bare coordinates) or not resolved yet is compared as text;
  - anything else by kind, name and city.
- Contacts (phones, @handles, emails) stay out of the public `catalog.json`. Build without `--contacts` unless the owner explicitly decides otherwise.

## Updating the catalog after a new export
1. The owner exports the channel with **Telegram Desktop**. The native macOS "Telegram" app cannot export.
   - Path: channel → ⋮ → Export chat history.
   - Settings: untick all media, format "Machine-readable JSON", period from the very first message.
   - The period must be all time, otherwise edited old posts are missed.
   - Don't copy the exported `result.json` over `work/result.json` by hand: the private channel-tools repo puts it in place (`sync_channel.py run --from <export>`), keeping posts changed only by its hashtag fix as they were. Without that repo, copy it over `work/result.json`.
2. `python3 -I tools/catalog.py diff`
   - It compares the export with `work/state.json`. Changed and new posts go to `work/inc/<tag>/`, together with their reply parent and direct replies for context. It also archives the export and updates `state.json`.
   - If it prints "no changes", stop.
   - If far more posts changed than the owner's edits explain (hundreds), stop and investigate before extracting; a new export format is a likely cause. To undo: copy `work/inc/<tag>/state_before.json` back to `work/state.json`, then delete `work/inc/<tag>/` and `work/exports/<tag>.json`.
3. Extract every pending part. `python3 -I tools/catalog.py pending` prints `{root, pairs}`.
   - For 1–3 parts, do it yourself: read `tools/extract_prompt.md` and follow it for each pair.
   - For more parts, run `tools/extract_workflow.js` with the Workflow tool, passing the printed JSON object as `args`. This needs the owner's OK; the prompt in README.md gives it.
   - Repeat until `pending` prints no pairs.
4. `python3 -I tools/geo.py resolve` opens the new map links (seconds for a day's posts; it needs network access to maps.app.goo.gl and goo.gl). If Google answers with a block or a captcha, it stops; build anyway and the new places get their region next time.
5. `python3 -I tools/catalog.py build`
   - It refuses while parts are pending.
   - Read its report: item counts before and after, names added and gone, skipped entries, map-link coverage. Names gone should be explainable by the edits.
6. Spot-check a few added items in `docs/catalog.json`, and check that `git status` shows nothing from `work/`.
7. Commit `docs/catalog.json` and push. Pages redeploys in about a minute.
   - Check that https://skirpichenko.github.io/my-chiang-mai/catalog.json shows the new `built_from_posts_until`.
   - Inside the Claude Code sandbox, git writes to `.git` fail with "Operation not permitted". Run git commit and push with the sandbox disabled for that one command.
8. Then the private channel-tools repo updates the English post translations and the English catalog, which rewrites `docs/catalog.en.json` here. Commit and push that file too.

## Full rebuild (only when the extraction spec changes)
1. Move `work/out` and `work/inc` aside; do not delete them.
2. Run `python3 -I tools/catalog.py split`. It writes 70 or more parts to `work/chunks/` and resets `state.json`.
3. Extract all parts with the workflow (about 18 agents, about 45 minutes, about 4.4M tokens).
4. Run `build`, then compare its report with the old catalog before publishing.

## Conventions
- Run Python that reads the export with `python3 -I`. The pipeline needs only the standard library.
- The owner usually writes in Russian. The channel's author edits posts from a phone and does not use these tools.
